## Â§1. Severity System (SINGLE AUTHORITATIVE COPY â€” S7 fix)

| Level | Definition | Ship blocker? |
|-------|-----------|---------------|
| CRITICAL | Revenue-blocking, data-loss, security vulnerability | YES |
| HIGH | Trust-damaging, broken user flow, wrong content, untraceable artifact | YES |
| MEDIUM | Polish gap, inconsistency, non-blocking | NO |
| LOW | Cosmetic, preference | NO |

Rule: A CRITICAL or HIGH finding on any check FAILS the prompt. MEDIUM and LOW are recorded but do not block.

### Report color vocabulary (sweep report visualization only)

| Primary level | Report color |
|--------------|-------------|
| CRITICAL | RED |
| HIGH | RED |
| MEDIUM | AMBER |
| LOW | GREEN |

The GREEN/AMBER/RED system appears only in /docs/sweeps/full-report.md. Never in Acceptance Criteria, Verification Artifacts, or Gate Checks.

### Specific rulings

- Border-radius inconsistency: MEDIUM (non-blocking). Not a FAIL condition.
- Touch target size: PASS at 44px+ (WCAG 2.1 AA minimum). FAIL under 44px. 48px recommended best practice, not a FAIL threshold.
- Extension point not tracing to a non-goal: HIGH (blocking). This is a scope violation. (S5 fix â€” was incorrectly listed as MEDIUM in v1.1.)

## Â§6. Provenance Chain â€” Authoritative Specification (S1 + S2 fix)

### Chain structure

The chain runs through verification artifacts. Every prompt computes an `artifact_hash` (SHA-256 of its primary output artifact) and a `prevHash` (link to the previous verification artifact or gate hash).

- Prompt 01: prevHash = "GENESIS", artifact_hash = SHA-256(/docs/discovery-brief.md)
- Prompt 02: prevHash = SHA-256(prompt-01 verification file contents), artifact_hash = SHA-256(/docs/architecture.md)
- ...continuous through Prompt 10...
- Gate 1: gate_1_hash = SHA-256(byte_concat(artifact_hash_01, artifact_hash_02, ..., artifact_hash_10))
- Prompt 11: prevHash = gate_1_hash (NOT SHA-256 of prompt-10's verification file)
- ...continuous through Prompt 25...
- Gate 2: gate_2_hash = SHA-256(byte_concat(artifact_hash_11, artifact_hash_12, ..., artifact_hash_25))
- Prompt 26: prevHash = gate_2_hash (NOT SHA-256 of prompt-25's verification file)
- ...continuous through Prompt 47...
- Gate 3: gate_3_hash = SHA-256(byte_concat(artifact_hash_26, ..., artifact_hash_47)) = product's final provenance seal

### Chain verification procedure (S2 fix â€” with explicit stage-boundary exceptions)

To verify the chain at any point:

1. **For all prompts EXCEPT 11 and 26:** Read prompt N's verification file. Compute SHA-256 of prompt N-1's verification file contents. Confirm it matches the `prevHash` field in prompt N's file. If mismatch, chain is broken at prompt N.

2. **For Prompt 11 specifically:** prevHash is NOT the hash of prompt-10's verification file. It is `gate_1_hash`. To verify: recompute gate_1_hash = SHA-256(byte_concat(artifact_hash_01 through artifact_hash_10)) using the artifact_hash values recorded in prompt-01 through prompt-10 verification files. Confirm it matches the `prevHash` field in prompt-11's file.

3. **For Prompt 26 specifically:** prevHash is NOT the hash of prompt-25's verification file. It is `gate_2_hash`. To verify: recompute gate_2_hash = SHA-256(byte_concat(artifact_hash_11 through artifact_hash_25)) using the artifact_hash values recorded in prompt-11 through prompt-25 verification files. Confirm it matches the `prevHash` field in prompt-26's file.

### Definition of || (S2 fix)

`||` means byte concatenation. Specifically: the raw bytes of each artifact_hash string (64-character hex string encoded as UTF-8) are concatenated in order, then the resulting byte sequence is hashed with SHA-256.

### Worked example (S2 fix)

Gate 1 verification for a product where:
- Prompt 01 artifact_hash = "a1b2c3..." (64 hex chars)
- Prompt 02 artifact_hash = "d4e5f6..." (64 hex chars)
- ... through Prompt 10 artifact_hash = "z9y8x7..." (64 hex chars)

```
gate_1_input = "a1b2c3..." + "d4e5f6..." + ... + "z9y8x7..."  (640 bytes of UTF-8 hex chars)
gate_1_hash = SHA-256(gate_1_input)  (64 hex chars output)
```

Prompt 11's verification file must contain:
```
prevHash: [gate_1_hash value]
```

To verify: recompute SHA-256(byte_concat(artifact_hash_01, ..., artifact_hash_10)) and compare.
